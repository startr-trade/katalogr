# katalogr v0.2.0

The second feature release. v0.1.x indexed a polyglot repository and answered questions about it from the command line and from Claude Code. v0.2.0 adds what people need to see and trust the answers: impact analysis, type lineage, a dependency inventory, diagrams and an embedded web view, static exports for reviewers, a versioned contract that kanbanr reads views through, branch and worktree contexts, exact-position answers, snapshots and audit records, a stateless API server, multi-repository workspaces, and a user guide. The index data no longer lives in git.

## Commit

The code is the commit this tag names, on `main`. Its CI run, on Linux, macOS and Windows, succeeded before the release workflow built anything, and the no-C build proved again that katalogr builds with nothing beyond cargo.

## Highlights

- **Impact analysis** (`katalogr impact <symbol | file | git range | board item>`): what a change reaches, across languages and repositories, grouped by link kind and confidence, with a stable JSON schema for PR checks. See [Impact](../features/impact.md).
- **Type lineage** (`katalogr lineage`): where a type or schema element flows across artifacts, bounded by depth and limit. See [Lineage](../features/lineage.md).
- **Dependency inventory** (`katalogr deps`): every package a lockfile pins (Cargo, npm, pnpm), who pins it and which code uses it. See [Dependencies](../features/dependencies.md).
- **Diagrams** (`katalogr render`): structure, impact, lineage, service-map and other views as Mermaid, DOT, GraphML, Structurizr or SVG laid out in pure Rust; an mdBook preprocessor and a Markdown filter replace `katalogr-query` blocks at doc build time; `katalogr view check` and `view snapshot` keep a board's query blocks honest without writing diagrams into it. See [Views and diagrams](../features/views-and-diagrams.md).
- **Web view and exports** (`katalogr serve`, `katalogr export html|graph`): a read-only web view compiled into the binary (graph explorer, service map, impact, symbol pages, dependencies, type lineage, health and a timeline), and one self-contained HTML file for reviewers who have nothing installed. See [Web view and exports](../features/web-and-exports.md).
- **Contexts and positions**: a linked worktree or branch gets its own view of the index by default; every answer names the exact position it was computed at, and `--at <position>` asks for that position again. See [Change and history](../features/change-and-history.md).
- **Workspaces**: several repositories per project, and peers across projects, linked through matched contracts. See [Workspaces](../features/workspaces.md).
- **A versioned contract for tools** (`katalogr contract`): kanbanr and other clients ask for views by ID through a documented, versioned surface; the stateless `katalogr api` server answers them over HTTP on loopback.
- **A user guide**: getting started, using katalogr from Claude Code, connecting it to kanbanr projects, and connecting other agent hosts through MCP. See [the guide](../guide/index.md).

## What changed

### Answers you can act on

- `impact` seeds from a symbol, a file, a git diff range (each hunk seeds the innermost symbol it touches; a deleted file seeds the references it breaks) or a kanbanr item, and reports dependents, tests, contracts and docs.
- `lineage` follows a type or a schema element through fields, codecs, routes and tables. Its walk is bounded by depth, limit and per-group caps and stops at code, so it stays fast on dense graphs.
- `docs-affected` lists the documents linked to code that changed since a commit (the merge base by default), across repositories.
- `why` answers across katalogr and kanbanr: the annotation on the line, else the trailer of the commit that wrote it, then the requirement, item and goal.
- `deps` lists packages from Cargo, npm and pnpm lockfiles with `used_by` links into the code; the web view has a Dependencies page.
- `--diagnostic` prints why a result ranked or packed as it did.

### Views, diagrams and the web

- `render <view>` writes Mermaid, DOT, GraphML, Structurizr or SVG. Views are stored by ID and answered from the store, so two tools drawing the same view get the same bytes.
- `katalogr mdbook` and the Markdown filter embed live diagrams in documentation builds.
- `view check <path>` validates the query blocks in a folder of docs; `view snapshot --docs <dir> --out <dir>` writes each block's view for a position as Markdown with Mermaid and as JSON. katalogr never writes into a board.
- `serve` runs the web view beside the API on loopback, with assets compiled in and no JavaScript build step. kanbanr's monitor opens the graph explorer, impact and service map by link.
- `export html --out <file>` writes one offline file holding the views and their data; `export graph --format dot|graphml|json` writes one view for Gephi, yEd or Cytoscape.

### Index lifecycle, positions and contexts

- **Index data leaves git.** A kindex no longer stores index shards; the cache under `.katalogr/` is the index, rebuilt by re-extraction when it is lost or the schema changes, with crash injection and determinism tests behind it.
- **Positions and `--at`.** Every answer carries the position (the commits and the dirty hash of every repository) it was computed at; `--at` asks for an exact position and exits 6 when it is not held.
- **Contexts.** A branch checkout or a linked worktree gets its own context, seeded from the base in seconds, and a plain `index` keeps it fresh; `context list|show|add|prune|diff|conflicts` manage them. Pinned repositories read the pinned commit.
- **Working set and `watch`.** Answers favour the files you are editing (dirty files, the branch's files, the item's files), and `watch` keeps the index fresh at a fixed cost per idle tick.
- **Snapshots** (`snapshot export|import|show`): move an index between machines or into CI as one `.ksnap` file, checked by a whole-file checksum.
- **Audit records** (`audit record|verify`): prove that a rebuild at the same positions reproduces the same index digest.
- **`diff <a> <b>`**: a semantic diff report between two commits or releases as Markdown, JSON and static HTML, written only where you send it.
- **Stored answers.** Whole-graph answers (hubs, communities, cycles, dead code, coverage, map) are stored by view ID and reused while their inputs are unchanged.
- **The scan honours git's ignore rules**, and a plain `index` picks up edits in a project's second repository.

### Workspaces and the API

- `workspace status|map` across several repositories and across projects, with peers named in the kindex. Inter-repository dependencies are traced in both directions through matched contracts.
- `katalogr api` serves the same operations as the CLI over HTTP on loopback, stateless, with parallel readers; `contract` prints the versioned surface (contract version 8) and the capabilities present.
- The MCP server's tools now include impact, lineage, deps, diff and views; see [Connecting MCP agent hosts](../guide/mcp.md).

### Extractors

- Rust: calls inside the arguments of standard macros (`assert_eq!(f(x), y)`, `println!`, `vec!` and others) are linked.
- Schemas: field-level symbols for code types (`field_type` facts) feed lineage.

### Build, CI and the release

- The user guide is built with the book and checked in CI: every page is listed and every command it names exists.
- Windows CI runs on a Dev Drive with the same tests as Linux and macOS. Workflows are linted with actionlint; release builds keep a per-target dependency cache.
- `gix` 0.90, which closes the repository's one code-scanning alert.
- Release notes are the GitHub release's body and are on the documentation site.
- The web view and exports carry the katalogr favicon.

### Fixed

- Snapshot export of a two-repository project when the second repository had no recorded position.
- A flipped byte in a `.ksnap` file was sometimes accepted; snapshot files now carry a whole-file checksum and `show` refuses a damaged file.
- The web view's Dependencies page always read as absent.
- `render --help` and `view --help` did not name every view op.
- Lineage at depth 3 could grow memory without bound on a cyclic graph.
- The self-index cache was seven times its size after a full index, because compaction ran before the base advance.
- A save in a plain (non-git) folder took eight seconds to reach a fresh answer.
- SVG rendering of a dense structure view never finished (a patched copy of `layout-rs` is vendored under `vendor/`, MIT, with the fix recorded for upstream).

## Upgrading from v0.1.x

- **Re-index once.** The index data format changed (index data left git). Run `katalogr index --full` in each project after installing v0.2.0, then `katalogr doctor`; see [Index lifecycle](../features/index-lifecycle.md).
- **Contract clients** read `katalogr contract` for version 8; views, impact, lineage and deps are capabilities a client checks before asking.
- **Snapshots** made by v0.2.0 are format 1 and are valid for the same cache schema only; keep them with the binary that wrote them.

## Known limits

- An SVG of a very dense view (hundreds of nodes with many crossings) can take seconds: the layout crate's crossing minimiser is slow, and `--max-nodes` keeps views small.
- The corpus benchmarks (full index, stored answers, diff, snapshot round trip) were measured on synthetic fixtures for this release; the real-corpus runs are recorded on the board when they are done.
- Windows CI time is measured against its baseline after this release's push.
