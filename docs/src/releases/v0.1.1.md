# katalogr v0.1.1

A patch release of [v0.1.0](v0.1.0.md). v0.1.0 was tagged while its CI was failing. It passed on Linux and macOS, but on Windows it neither compiled nor ran: every index failed there with "Access is denied". No v0.1.0 binaries were published. v0.1.1 fixes katalogr on Windows, makes sure a release can never again be cut from a commit whose CI has not passed, and adds the katalogr logo.

## Commit

The code is the commit this tag names, on `main`. Its CI run, on Linux (`ubuntu-24.04`), macOS (`macos-15`) and Windows (`windows-2025`), must succeed before the release workflow builds anything (see **Release gate** below).

## What changed

### Windows (FEAT-109)

Three CI runs on Windows found and fixed:

- **Indexing on Windows.** katalogr flushed folders to disk by opening them as files, which Windows refuses. This happened in the inbox, the cache publish step and cache compaction. Directory flushes now run only on Linux and macOS; NTFS records the rename itself.
- **Repository roots.** On Windows, a resolved path takes the `\\?\C:\...` form. In that form `/` is not a separator, so every repo-relative file under such a root would have been "not found". Roots are now stored in their plain form, `C:\...`.
- **Portable files and reports.** The `.katalogr` marker is committed and read on other machines, so it now records the kindex path with `/`. `katalogr doctor` lists quarantined shards with `/`. `.gitattributes` keeps text files at LF on every system.
- **Benchmark timeouts** now end the child process on Windows too.

On Windows, `katalogr` compiles and its whole test suite passes in CI.

### Release gate and CI

- **A release waits for CI.** `release.yml` first checks the CI run on the tagged commit. A failed or missing run refuses the release; a run still in progress is waited for. Every release also re-proves that katalogr builds with no C compiler, and publishing waits for that proof.
- **One pinned toolchain** (Rust 1.99.0) in `rust-toolchain.toml` and in every workflow. A new clippy release can no longer fail a build that passed the day before.
- **`make ci`** runs, locally, what CI runs: fmt, clippy, clippy for Windows and both macOS targets, the tests, the crash suite, the retrieval gate, and the no-C build when dependencies change. With cargo-nextest installed, the test suite takes about 3 minutes.
- **Faster, steadier CI.** CI caches compiled dependencies and runs tests with cargo-nextest. It runs on pushes to `main` and on pull requests, cancels runs a newer push has made pointless, pins its runner images, and runs the no-C build only when dependencies change, nightly, and at release.

### Brand (FEAT-108)

The katalogr mark (a catalogue card on its rod, its thread leading to what it names) appears on the README and the documentation site. The site also gets a favicon, and there are an app icon, light and dark lockups, and a social preview card. The sources are in `assets/brand/`. Under the wordmark, the name's origin: κατάλογος, Greek for a register or list.

## Install

As for v0.1.0. The archives are named `katalogr-v0.1.1-<target>`.

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/startr-trade/katalogr/releases/latest/download/install.sh | sh
```

## Limits

v0.1.0's limits still apply. The web view's favicon is not in this release: v0.1 has no web view, and the favicon ships with it in v0.2.0.
