# katalogr v0.1.0

katalogr builds a deterministic graph of the code, documents and schemas in a repository, and lets you ask it questions: who calls this, what does this link to, which tests cover it, where are the hubs and cycles. It is one binary with no runtime dependencies. It works from the command line without any agent or editor, and it also ships a Claude skill, Claude hooks and an optional MCP server for other AI hosts.

This is the first release. Read **Limits** before you point it at a very large repository.

## Install

Once the release is published:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://github.com/startr-trade/katalogr/releases/latest/download/install.sh | sh
```

The script picks your platform, downloads the archive, verifies it against `SHA256SUMS` (it refuses a mismatch) and installs `katalogr` into `~/.local/bin`. Use `--dir PATH` to choose another folder and `--version vX.Y.Z` to pin a version.

**The one-liner does not work yet.** The repository is public, but the release is not published, so there is nothing for the URL to download. Until then, build from source with only a Rust toolchain: `cargo build --release --locked -p katalogr`.

First steps, on any repository:

```sh
katalogr kindex init ~/kindex                      # where index data lives, outside your repository
katalogr --kindex ~/kindex --project demo project init demo --repo "demo=/path/to/repo"
cd /path/to/repo
katalogr --kindex ~/kindex --project demo index --full
katalogr --kindex ~/kindex --project demo map      # the most connected symbols
katalogr --kindex ~/kindex --project demo callers <symbol>
katalogr --kindex ~/kindex --project demo doctor --skip-git
```

## What is in this release

- **The graph.** A language-neutral artifact graph with contract-mediated linking: code that meets across a boundary (a REST route, a WASM export, a SQL object, a schema) is linked through the contract, not by guesswork. Index data lives in a "kindex" repository separate from your code.
- **Extractors.** Rust; TypeScript and JavaScript (ESM `.js` specifiers resolving to `.ts`, CommonJS exports, `extends`, constructor calls); SQL; Markdown; XSD and JSON Schema; OpenAPI; JSON, YAML and XML as key trees; a text fallback that makes unclaimed files searchable when you opt in per glob. Linkers join REST, WASM, and documents with kanbanr items.
- **Queries.** `find`, `refs`, `callers`, `explain`, `tests` (symbol to test linkage), `path`, `search` (prefix and partial-term matching), `map`, `hubs`, `communities`, `cycles`, `dead-code`, `coverage` (resolved, inferred and unresolved references per language), `dangling`, `session-start`, and `doctor` (index health checks with recommended fixes).
- **Indexing.** Parallel, with byte-identical results for the same input; a change queue with consistency modes (`wait` or `stale-ok`); incremental re-index of changed files; crash recovery. A full index of a 34k-file Rust and TypeScript project that used to run past six hours and leave a 12 GB index now finishes in minutes (see Measured).
- **Agents, optionally.** A Claude skill and hooks, and `katalogr mcp` for Codex, Cursor and Windsurf. Everything also works without an agent.
- **Quality.** A retrieval evaluation harness with golden sets and a CI gate (0 regressions in 138 cases at this commit), and a repository privacy check in the test suite.
- **Fixes since the first drafts.** A symbol and its own re-export no longer make a name ambiguous; inferred method-name links (such as every `.map()` counting towards one symbol) no longer flood rankings; an email address in a document is no longer a dangling link; `explain` works on contract names; text-fallback files are no longer counted as both indexed and unclaimed.
- **Cache and query speed at scale.** The cache is smaller (4.4 bytes per source byte on this repository, 3.4 on a Rust corpus), PageRank is cached at publish so `session-start` and `map` stay fast, and queries read from a compact symbol core.

Work items shipped (code and title; GitHub cannot resolve board links): FEAT-001 universal artifact graph, FEAT-002 contract-mediated linking, FEAT-003 kindex repository, FEAT-004 query CLI, FEAT-005 Rust extractor, FEAT-006 TypeScript/JavaScript extractor, FEAT-008 extension model, FEAT-009 XSD and JSON Schema, FEAT-014 REST linker, FEAT-016 WASM bridge linker, FEAT-017 SQL extractor, FEAT-019 docs and kanbanr linker, FEAT-023 acceptance harness, FEAT-024 Claude skill, FEAT-025 token-efficient retrieval, FEAT-026 Claude hooks, FEAT-030 structure insights, FEAT-047 change queue, FEAT-051 TypeScript/JavaScript extraction fixes, FEAT-052, FEAT-053, FEAT-056, FEAT-058, FEAT-069, FEAT-073, FEAT-074 bug fixes, FEAT-055 prefix search, FEAT-057 cached PageRank, FEAT-059 contracts in the canonical graph, FEAT-061 evaluation harness, FEAT-062 coverage report, FEAT-063 test linkage, FEAT-064 doctor, FEAT-066 text fallback, FEAT-067 MCP wrapper, FEAT-072 parallel indexing, FEAT-075 cache size, FEAT-076 query latency at scale, FEAT-077 inferred fan-out, FEAT-079 XSD extraction at scale, FEAT-080 queries during a full index, FEAT-093 full index at scale, FEAT-100 public repository files, and FEAT-022 distribution (single binary and install script).

## Measured

Machine: Intel Core i7-10750H, 12 logical CPUs, 45 GiB, ext4, Linux 7.0. Release builds, `KATALOGR_THREADS=4`, an 8 GB memory cap per run. **Every run was on a loaded machine**, shared with other work (1-minute load 6 to 19), so read the numbers as rough upper bounds, not benchmarks. An idle re-measure follows as FEAT-107. Index sizes are shard files plus the local cache, in MiB.

The small corpora (tier S) were measured on this release's binary, commit `905ee38a547c`, one corpus at a time. The large ones (tier M) were measured at `3b14900`; nothing in the shipped binary has changed since, only the bench harness.

**Small public corpora** (full index from scratch, median of 3 cold runs, identical results each time):

| Corpus | Files indexed | Shards + cache MiB | Wall s | Peak RSS MiB |
|---|---|---|---|---|
| mdn/content docs (Markdown) | 14,742 | 98 + 113 | 93.6 | 390 |
| PostgreSQL (SQL) | 3,412 | 144 + 197 | 70.4 | 838 |
| SchemaStore (JSON Schema) | 1,032 | 276 + 260 | 71.2 | 945 |
| W3C xsdtests (XSD) | 15,401 | 93 + 86 | 74.5 | 604 |

Queries on these, p95: point queries (`refs`, `callers`, `explain`, `tests`) take 4 to 50 ms, `find` 71 to 122 ms, `path` 6 ms to 0.4 s, `search` up to 1.6 s (mdn/content), `session-start` 52 to 96 ms. Graph-wide commands (`map`, `hubs`, `communities`, `cycles`, `dead-code`, `coverage`) take 0.3 to 9 s; the slowest are `communities` at 9.0 s and `hubs` at 7.8 s on the XSD corpus. No query returned an error. Re-indexing after a real commit takes a median of 1.4 to 6.0 s (p95 up to 8.3 s).

**Large public corpora** (tier M):

| Corpus | Files claimed | Index wall s | Peak RSS MiB | Shards + cache MiB | `session-start` p95 ms |
|---|---|---|---|---|---|
| polyglot (Rust, TypeScript, WASM) | 12,541 | 101.8 (median of 3) | 1,852 | 342 + 292 | 29.7 |
| Go | 11,875 | 53.6 | 1,051 | 192 + 276 | 26.8 |
| Java | 36,883 | 200.5 | 2,912 | 695 + 1,125 | 37.4 |
| TypeScript, extra large | 16,030 | 261.1 | 3,910 | 1,906 + 1,999 | 42.8 |
| C# | 22,427 | 148.1 | 3,256 | 668 + 1,023 | 33.9 |

Re-indexing after a real commit takes a median of 1.6 to 10.8 s (p95 up to 21.7 s) with 0.7 to 2.8 GB. No query returned an error. Repeated index runs were byte for byte identical.

Indexing while four readers query: on the small corpora the index slowed by 1.24x (PostgreSQL), 1.52x (SchemaStore), 1.24x (mdn/content) and 0.95x (XSD), against a limit of 1.15x, with no query errors and identical results afterwards. On the loaded machine the harness cannot say how much of that is load. On the large polyglot corpus it slowed 1.27x.

Some limits were revised during the release: after the cache follow-up, decode speed against JSON came in at 0.17x (links) and 0.54x (symbols), within their limits; postings cost per artifact is 1.01x the old layout against a revised limit of 1.1x, and compaction rewrite is 12.8% against a revised 15%. The 0.5x postings and 5% rewrite limits originally set were not achievable with the storage engine.

## Limits

Stated plainly, because they will affect you.

- **Large graphs are slow for some commands.** On the largest graphs, `tests` and `path` take 6 to 50 seconds at p95 (the polyglot corpus: `tests` 6.5 s, `path` 49.4 s; the extra large TypeScript corpus: `tests` 32.8 s, `path` 20.5 s). Graph-wide commands (`map`, `hubs`, `communities`, `cycles`, `dead-code`, `coverage`) take seconds there, up to 24 s for `communities` on the extra large TypeScript corpus. Point queries (`find`, `refs`, `callers`, `explain`) are fast on most corpora, but `callers` and `explain` took 1.8 s and 1.1 s on the extra large TypeScript one. Tracked as FEAT-103, FEAT-104 and FEAT-105.
- **Memory with a writer and several readers.** An index running beside four query processes on a very large corpus can exceed 8 GB combined. In the load test the Java, extra large TypeScript and C# runs were killed at an 8 GB cap. Run one writer with at most one or two readers on repositories of that size, and give the machine room.
- **Install.** The repository is public, but the curl one-liner works only once the release is published; until then, build from source.
- **Platforms.** Linux musl (x86_64) was tested locally end to end. aarch64 Linux was checked as static but not run. macOS and Windows binaries are first built by the tag's workflow and are untested until then. The Intel macOS build uses a GitHub runner whose support ends in 2027, after which that target will be dropped or moved.
- **Index data is shard files in the kindex's git.** They can reach hundreds of MB per project (about 1.9 GB of shards for the extra large TypeScript corpus), and a later format change may require a re-index. v0.2.0 moves index data out of git.
- **Checkouts.** Linked git worktrees of one repository share a single index until FEAT-043 and FEAT-085.
- **No position or view ID on answers** until FEAT-084.
- **Queries during an index.** A plain read waits for the whole index to finish, up to `--timeout`, then exits with code 5. `stale-ok` answers at once from the last published state (FEAT-080).
- **Git-ignored files** that an extension claims are indexed unless the repository's `exclude` covers them.
- **Language support.** Extractors exist for Rust, TypeScript/JavaScript, SQL, Markdown, XSD, JSON Schema, OpenAPI and data documents (JSON, YAML, XML), plus the WASM, REST and kanbanr linkers. Go, Java, C# and the other languages of the charter have no extractor yet: their files are searchable through the text fallback if you opt in, but have no symbols or call graph. Their tier M timings above measure what katalogr does on those repositories today.
- **Measurements** are from a shared, loaded machine (an idle re-measure is FEAT-107). Indexing beside four readers slowed by more than the 1.15x limit on three of the four small corpora.
